# CU23 y CU24 — Push y ayuda contextual

## Configuración Web Push

El backend usa VAPID y conserva la clave privada exclusivamente en el entorno del servidor.
Para generar un par local puede utilizarse la herramienta estándar de `web-push`:

```bash
npx web-push generate-vapid-keys
```

Copiar los valores a un `.env` local que no se publique:

```properties
VAPID_PUBLIC_KEY=<clave pública base64url>
VAPID_PRIVATE_KEY=<clave privada base64url>
VAPID_SUBJECT=mailto:responsable@ejemplo.com
PUSH_ENABLED=true
```

No copiar la clave privada a variables `VITE_*`, JavaScript, capturas, commits ni documentación.
El frontend obtiene únicamente la clave pública desde un endpoint autenticado.

La aplicación mantiene su estrategia actual `spring.jpa.hibernate.ddl-auto=update`. Al arrancar,
Hibernate crea las tablas `push_subscription`, `push_preference` y `push_delivery`; no se requiere
borrar datos ni recrear volúmenes. Para un despliegue productivo posterior conviene capturar ese
esquema en la herramienta de migraciones elegida por el proyecto antes de desactivar `ddl-auto`.

## Compatibilidad

- Android/Chrome: HTTPS y permiso concedido por el usuario.
- iOS/iPadOS: versión compatible, aplicación instalada en la pantalla de inicio y abierta desde allí.
- `localhost`: los navegadores lo consideran contexto seguro para desarrollo.
- Una IP LAN mediante HTTP no es contexto seguro y no debe usarse como prueba de Push API.
- En AWS debe terminarse TLS/HTTPS antes de realizar la prueba física.

## Eventos soportados

- Invitación persistida a proyecto.
- Recomendación aplicada y confirmada.
- Guardado UML relevante, si el destinatario activó esa preferencia.
- Decisión del sistema que no duplique la aplicación de una recomendación.
- Mención inequívoca mediante `@correo-completo` de un miembro activo.

Los consumidores se ejecutan después del commit. Se vuelve a verificar la membresía, se excluye al
actor, se deduplica por evento/usuario/dispositivo y se desactivan endpoints 404/410.

## Ayuda contextual y mecanismo de aprendizaje

La ayuda consulta `help/knowledge-base.json` mediante endpoints autenticados de solo lectura. La
búsqueda normaliza acentos, reconoce sinónimos controlados y exige una coincidencia funcional antes
de usar el contexto de la pantalla; el contexto nunca selecciona por sí solo una respuesta.

El panel global ofrece **Preguntar** y **Manual y tutorial**. El segundo modo implementa la experiencia
de aprendizaje solicitada en la sección 8 del documento oficial: temas navegables, búsqueda, pasos,
permisos y enlaces a rutas existentes. La documentación independiente está en
`docs/MANUAL-USUARIO.md` y `docs/TUTORIAL-USO.md`.

Las respuestas frecuentes no invocan el pipeline generativo. Una solicitud de crear, borrar o
modificar UML se rechaza y orienta al Chat del proyecto y su flujo de aprobación. La ayuda tampoco
expone contraseñas, tokens, correos privados o datos de otros proyectos, y no existe ningún endpoint
de ayuda que escriba sobre proyectos o diagramas.
